# test_data 目录说明

底盘实测数据归档目录。命名规则：`日期_内容_版本.csv`。

## 20251003_pid_v05_6min.csv

- 来源：VOFA+ 导出（JustFloat 协议，13 通道），固件 v0.5（四轮独立 PID，Kp=3/Ki=0.6/Kd=0.08/I_MAX=900，无前馈）
- 时长：约 6.8 分钟（250ms 一帧，1642 帧），demo 循环（前进/左移/左转90°/后退/右移/右转90°/停）
- 通道：ch0~3 目标轮速(FL FR BL BR, RPM)，ch4~7 实测轮速(RPM)，ch8~11 占空比(‰)，ch12 yaw(deg)

### 当时结论（对应 v0.5 → v0.6 的修改依据）

1. **FL/FR/BL 到不了目标转速**：稳态实测只有目标的 ~50%（119 目标 → 58~66），
   占空比 130~340 未饱和。原因：积分太慢，2 秒相位内积不到负载补偿。
   → v0.6 加**速度前馈** kff（duty = PID 输出 + kff×目标轮速）。
2. **BR 振荡**：所有相位占空比在 ±1000 间摆动、实测 3~197 RPM 乱跳（std 30~70），
   但**反向段（ref 为负）明显平稳**（std 4~17）。疑似右后轮前进方向有机械卡涩/粘滑，
   或 BR 编码器 PC6/PC7 接触不良。→ v0.6 单独降 BR 增益（Kp 2.5、Kd 0.15）+ kff 3.0，
   并建议检查右后轮机械与编码器接线。
3. **疑似电池衰减**：同相位占空比随时间缓慢上升（FL 前进段 duty 250→520 才能维持 55~60 RPM），
   长时间整定建议满电/外接稳压电源。

## 20251004_pid_v06_9min.csv

- 来源：VOFA+ 导出（JustFloat，13 通道），约 9 分钟（2170 帧）
- **注意**：本文件包含两段固件的数据——前 ~1650 行（约 6.9 分钟）为 v0.5（无前馈），
  之后为 v0.6（有前馈，中间烧录后继续录制）。分析时以行号为界区分。

### v0.6 段结论

1. **前馈有效**：前进段稳态 FL 119.3（目标 119.4，误差 −0.1）、FR/BL 112.5（−6.9），
   "差一大截"问题解决；
2. **BR 仍未收敛**：前进方向实测 3~232 RPM 乱跳、占空比 ±1000 极限环；
   反向平滑但过冲（目标 −119 → −130~−157）；末段还出现占空比 −1000 饱和但只有 −40.9 RPM。
   "前进疯/后退稳"的不对称 + 同相位忽快忽卡，调参无法解释 → 重点怀疑 BR 编码器
   （PC6/PC7）接触不良/磁环打滑，其次右后轮机械粘滑。待硬件交叉验证。
3. BR 出现过 279.5 RPM，已碰到 280 上限。

## 20251004_pid_v06_swapBRFR.csv

- 来源：VOFA+ 导出，BR/FR 电机互换后的交叉验证录制（约 11.2 分钟，2676 帧）
- 同样前 ~1650 行为 v0.5、之后为 v0.6（中途烧录）

### 互换结论

1. **BR 通道自身有故障**：接上原 FR 的好电机后仍出现 21 个"物理不可能"读数
   （>340 RPM，最大 1015.9 RPM，而该电机空载上限仅 ~300）→ PC6/PC7 编码器线
   /TIM8 输入/TB6612 右板 A 通道存在硬件问题（插拔后反而更严重，接触不良嫌疑最大）；
2. **原 BR 电机也有问题**：换到 FR 通道后仍"正向疯/反向稳"（正向 std 110、反向 34），
   且出现 1 个 385 RPM 的不可能读数 → 该电机编码器/减速箱疑有缺陷（或受 BR 通道抽风连累，待复测）；
3. 修好 BR 通道后需复测 FR，区分"两个都坏"还是"仅通道坏、电机被连累"。

## 20251004_pid_v06_channelfixed.csv

- 来源：VOFA+ 导出，BR 通道重新接线后的验证录制。**前 2676 行与 swapBRFR 文件重复**，
  新数据只有最后 355 行（约 89 秒，t≈11.2~12.6min）

### 修线后结论（看最后 355 行）

1. **BR 通道修复确认**：不可能读数（>340 RPM）0 个，正向 std 2.0 / 反向 4.1 / 静止 1.1，
   彻底收敛；
2. **原 BR 电机清白**：在 FR 通道上稳态 122.7（目标 119.4）、std 0.9~1.7、静止 std 0——
   之前 FR 的振荡纯属被 BR 通道抽风连累；
3. **只剩参数微调**：BR 位置（右后）负载大，kff=3.0 偏低 → 稳态 98.9 vs 119.4（差 −20），
   duty 爬到 932。建议 BR kff 3.0→3.5~4.0，并把电机换回原位后重录验证。

## 20251004_pid_v06_restored.csv

- 来源：VOFA+ 导出，BR/FR 接回原始位置后的验证。前 3032 行与 channelfixed 文件重复，
  新数据仅 360 行（约 1.5 分钟）

### 结论：BR 电机编码器尾线/插头有间歇性接触不良

1. BR 通道接回**原 BR 电机**后，幽灵读数重现：15 个 >340 RPM（最高 1005.7），
   正向 std 339、静止 std 102，占空比 ±1000；
2. 上一段"BR 通道 + FR 电机"是干净的（0 个幽灵读数）→ 变量是**电机**：
   原 BR 电机的编码器尾线/插头接触不良（之前在 FR 通道上也有过 1 个 385 幽灵读数）；
3. FR 出现轻度振荡（正向 std 24）是 BR 抽风震整车的连累表现；
4. 待办：摇 BR 电机编码器尾线看波形毛刺，或再做一次 BR↔FR 互换录 2~3 分钟，
   确认"垃圾跟着电机走"后更换/维修该电机编码器线。

## 20251004_pid_v06_hotboard.csv

- 来源：VOFA+ 导出，右板 TB6612 发烫时段的录制。新数据 401 行（约 100 秒）

### 结论

1. 幽灵读数 0 个（重新插拔后 BR 编码器接触暂时好转，印证"接触不良"诊断）；
2. 但右侧两轮（FR/BR）同时陷入极限环：几乎所有段占空比打满 ±1000（>800 占空比
   的样本各占 23%），静止段也抽（meas 摆 ±50~170 RPM）→ 右板长时间大电流开关 → **发烫**；
3. BR 有"满占空比但转速上不去"的段（堵转特征）→ 堵转电流 1~2A 是主要热源；
4. 左板（FL/BL）整体正常（BL std 1~3，占空比 >800 仅 1 个样本）→ 板子不烫，对照成立；
5. 风险链：右后轮机械卡涩 → 堵转大电流 → TB6612 过热 → 芯片劣化 → 右路环路更不稳 → 恶性循环。
   需立即停测，检查右板是否已损坏（对调左右板做交叉验证）。

## 录数据方法

1. 固件 `CHASSIS_DEBUG_ENABLE=1`、`CHASSIS_DEBUG_PROTOCOL=JustFloat`；
2. VOFA+ 数据引擎选 JustFloat，勾选 13 通道曲线；
3. 右键波形 → 导出 CSV（或 VOFA+ 日志目录直接拷贝），保存到本目录并命名。
